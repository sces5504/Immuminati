## 3. 最新玩法目標與範圍

目標是讓現有 M1 的細胞行為與免疫因果可理解、有策略，完成本輪八項。免疫學採有標示的簡化，不宣稱完整人體模擬。

- 保留現有可玩的循環：觀察感染 → 暫停安排調理／支援／調度 → 恢復時間 → 自主接近與吞噬 → 依感染與組織結果調整。
- 已提出的具體優化：修正地圖拖曳反向；取消同區單位上限及目的地容量預留。舊全場 7 不應因程式方便自動作為新玩法的固定上限；若要保留任何全場供應限制，必須明示其用途及策略理由。
- 自主行為、招募／調理效益、資源、細胞差異、波次節奏與組織損傷是可優化對象；每次變更需說明解決什麼問題，用實際策略與試玩驗證。
- 本輪完成及驗證狀態以免疫擴充紀錄為準；後續候選不自動變成當輪全部工作。程式工作的優先順序依使用者當次任務執行。

## 4. 空間與鏡頭

維持現有三個相通防區、連續位置、通道、距離與接觸，以及現有鏡頭／選取方式。解剖分區仍可作資訊與支援目的地，不作同區駐守名額。

- 移除區域容量時，募集、移動、攻擊指定、存檔驗證與介面提示須同步處理，不能只把數值從 3 改成大數字，或把上限移到另一個隱藏檢查。
- 密集顯示可用既有列表、循環選取與視覺分散改善；不以模型重製或任意區域上限解決。
- 地圖採抓取式拖曳：滑鼠／手指向右，畫面地標跟著向右；向上也同向。保持現有拖曳手勢，只修正方向計算。
- 桌面、觸控、縮放及旋轉後同方向；投影、選取框與標記同步。拖曳放手不誤下移動命令，相機操作不改規則狀態。
- 未受邊界夾限時，拖曳 `(＋80, ＋40)` CSS px，地標投影約同向移動；測正反方向與不同視角，不能只確認鏡頭數值有變化。

### 4.1 統一的宿主組織與區室（使用者確認 v2.3）

每關都必須有可辨識、可選取的宿主組織細胞，包含未感染細胞。部位差異由 tissue profile／內容與模型 adapter 決定，不能到病毒關才突然加入宿主。M1 以第一型／第二型肺泡上皮及微血管內皮為起點；口腔／腸道仍未完成關卡或器官精模。

- 肺泡腔、組織間質與血管腔皆為細胞外空間，但由不同屏障區隔。肺泡隔不是單一巨大細胞膜。以明確空間標記與可開啟剖面說明位置，不能只靠配色推測。
- 保留組織戰場及原選取操作；點組織細胞顯示種類、健康與感染狀態，局部剖視顯示細胞膜、細胞質、核及實際胞內來源。剖視開啟安全暫停，關閉由玩家恢復，不另跑小遊戲或另一套時鐘。
- 病原位置與存活分開：胞外菌群、宿主綁定的吞噬體／細胞質來源、感染宿主的細胞質／核區室。吞入不等於死亡、感染建立或抗原呈現；各狀態不能互相推定。
- M1 的主要繁殖來源為胞外肺炎鏈球菌。吞入後先保留活負荷，嗜中性 2 秒、巨噬／樹突 3 秒後完成一批殺菌。這是教學壓縮時間，不代表實驗／臨床時間；處理未完不能提早勝利。新規則不對舊局已清除的病原補算。
- 健康宿主不得成為 NK／CD8 合法殺傷目標；補體／抗體不直接對胞內來源施放。感染宿主與吞噬細胞的胞內囊泡必須清楚區分。
- 組織細胞健康現階段映射既有防區保全，不能依可見細胞數重複扣損傷。屏障破壞、單細胞訊號／修復、病毒入侵／複製／釋出、胞內菌逃逸尚未完整建模，介面與交接如實標示。
- 血管／淋巴入口在組織側。募集以等待及跨屏障入口壓縮呈現，不能把血管或淋巴管畫成直接開在肺泡腔內。尚未逐層模擬穿越，不作真實比例宣稱。

## 5. 時間與權威結果

沿用固定步進、明確 seed／RNG、自主與手動共用作用機會。引擎先提交權威狀態及事件，展示再播放；動畫回呼不能計算傷害、資源、招募或勝敗。

- 現有暫停／恢復、加速、背景安全暫停及撤銷繼續可用；暫停不恢復資源、不縮短到場時間，背景不追算離線損傷。
- 動作不全局鎖住指揮，個別單位依合法冷卻與動作狀態作用。
- 相同 seed、帶步號的命令序列與固定步數，在不同速度／降低動態／略過展示下結算一致；加速不能跳規則步。
- 不因保留舊畫面而退回回合制或共用回合 AP。新增速度選項可列玩法便利性改進，不要求重建時間系統。

## 6. 自主行為優化原則

現有細胞在指定位置／目標及合法範圍內自主作用；優化時應提高可預期性與減少無效微操。

- 明確玩家命令優先，其次是巡防／自主目標。失效目標要能合理回到自主行為，不能永久待機。
- 不跨非法地形瞬移，不隔空吞噬；路徑、接觸距離、冷卻及作用條件由規則控制。
- 避免頻繁切換目標、卡路徑，以及玩家手動與 AI 重複使用同一作用機會。
- 既有細胞資訊與因果紀錄應能解釋「正在做什麼／為何無法作用」；按需要補文字，不為此另造一套 HUD。

## 7. 調理、募集與細胞差異

- 肺炎鏈球菌莢膜降低未調理吞噬效率；調理改善後續攝入／清除條件，不直接刪除菌群負荷。[B3][B10]
- 補體 C3b 支援即時可用；新生蛋白抗原特異性抗體須經呈遞、CD4／B 活化及漿細胞分化等待。不要假定補體終末裂解可普遍直接清空肺炎鏈球菌。
- 保留巨噬、嗜中性、樹突細胞的可辨識角色及合法作用差異；不同細胞不應只差名稱與顏色，也不能為追求平衡亂加沒有生物依據的攻擊技能。
- 募集保留資源成本、供應與到場延遲，從原微血管入口到場。取消區域名額後，以這些已有成本及壓力重新試玩，不無限免費生兵。
- 本輪以抽象引流淋巴結流程整合 DC → CD4 T → B／漿細胞，不另造 RTS 地圖；蛋白抗原與莢膜多醣路徑須區分。

## 8. 策略、節奏與組織

保留原關卡及三波作為平衡起點，不把舊數值全視為永久規格。調整成本、延遲、波次、作用差異或損傷時，記錄調整前後的影響。

- 至少保留兩種可行策略，例如較重早期調理與較重募集／調度，避免只有一套固定點擊順序能過關。
- 有壓力也有理解原因的時間；不以頻繁點擊或無提示爆量代替策略。使用者可暫停思考。
- 感染與組織損傷有因果；不能把每次免疫作用一律設定為固定傷害組織。若新增發炎取捨，先在現有資料／資訊層驗證，不強迫改成複雜模擬。
- 勝利需控制本局所有必要來源且維持必要組織；活病原、胞內來源或未處理的排程來源不能誤判已清除。失敗與星等原因可查。

## 11. 美術與動畫的保留邊界

沿用 `src/tactics/presentation/BattleScene.ts` 的場景、模型與動作，以及 `src/tactics/ui/TacticalApp.tsx`／`tactics.css` 的介面與響應式布局。本輪改善肺泡／微血管與細胞的連續形態、內部結構與獨立動作；不降級成佔位球體、不換整體畫風。

修復動畫錯位、目標殘影、選取對位、碰觸與狀態誤導屬可做的缺陷修正；應最小修改並留對比。吞噬保留接近、包覆、吞入及清除／存活差異，各單位保留獨立相位待機。不能為優化效能而刪除核心表演，也不能把現有模型降級成簡單圓球。

## 12. UI、百科與手機

既有桌面／直向手機全部必要操作繼續可用，主要觸控目標至少 44×44 CSS px。保留現有面板位置、風格、按鈕語意及資訊層級；條件改變後同步更新對應文字，不留下失效的容量數字或禁用理由。

百科、情境提示、因果紀錄、組織保全星等、鍵盤焦點、較大文字與降低動態繼續可用。遮住戰場的面板安全暫停，關閉由玩家恢復；不因新增功能讓手機主要動作離開可操作範圍。

## 13. 模組與存檔

保留既有 domain、content、engine、application、presentation、ui、persistence 分離。沿用既有機制的配置主要改內容；不要因玩法優化搬移整個專案或另外建立一套遊戲入口。

引擎可無瀏覽器運行，不讀動畫計時或全域亂數。規則變更牽涉驗證、內容、UI、存檔時同步修正，不能為新規則新增一個平行、互不相容的隱藏引擎。

保留 `immuminati:save:v1`、`immuminati:tactics:v2` 及存在的其他新版 key，不清空瀏覽器資料。若變更無法相容才明確升版並提供恢復／匯出路徑；不同規則檔不能默默當成同一局。匯入完整驗證成功才替換，失敗不覆寫原存檔。

## 14. 本輪新增與後續界線

本輪完成自主尋敵、局部 CXCL8／IL-12／IFN-γ／IL-10、發炎取捨、DC 引流與蛋白抗原呈遞、CD4／B 活化及漿細胞抗體。新細胞皆可依角色調度或募集；漿細胞由分化產生。CD8 在 M1 無合法殺傷對象與初始活化路徑，不能假裝靠 MHC-II 就能啟動；獨立演練示範預先活化 CD8 與 NK 的不同目標辨識。

器官解剖、細胞資料、免疫規則、展示與存檔分層。口腔／腸黏膜預留 profile 與建模分支，不代表後續關卡完成。新病原若沿用既有機制主要新增內容；新生物機制仍須擴充純規則及驗證。所有簡化需在面板、百科與交接列明。

- **B7**：[口腔上皮 IL-17 訊號與抗真菌防禦原始研究](https://pmc.ncbi.nlm.nih.gov/articles/PMC5147498/)。限定口腔黏膜情境。
