## 六關結果

以下是同一套合法UI策略在桌面與手機、正式建置與實際公開站的結果。秒數是教學壓縮模擬時間，不是臨床病程。

| 關卡 | 結果 | 組織保全 | 模擬時間 |
|---|---|---:|---:|
| M1 肺炎鏈球菌 | 三波來源清除，3星 | 88% | 83秒 |
| M2 Typhimurium | 胞外及囊泡內來源清除，3星 | 90% | 102秒 |
| M3 結核 | 穩定圍堵，仍有活菌；3星，不表示治癒 | 95% | 82.2秒 |
| M4 流感 A | 胞外與產毒宿主來源清除，3星 | 87% | 130.6秒 |
| M5 白色念珠菌 | 酵母／菌絲感染來源清除，3星 | 99% | 78.2秒 |
| M6 HIV | 有限觀察結果，保留潛伏來源，無一般勝利／星等 | 93% | 81.4秒 |

## HIV 的合法策略對照

另外以同一初始 seed、純規則引擎及合法招募命令試算，沒有移除細胞或注入數值。只觀察79.8秒；增加CD8與pDC為81.4秒；增加pDC支援84.2秒；增加巨噬與pDC為87.6秒且末期負荷較低，但組織保全90%而非93%。晚建立Tfh／B支援並未自動改善結果。所有情況均保留潛伏來源、有限結果及零星等。

這組對照表示決策會影響局部控制與支援時間，不是固定倒數結局，也不宣稱其數值能預測臨床。[原始命令與數值](evidence/campaign-final/hiv-legal-policies.json)。

## 候選版瀏覽器修正（發布前）

- 第一次 CI 阻擋發布：新增抗體說明另占一整行，使手機菌群被募集工具遮住；改為同一抗體工具列內的獨立44px說明入口，恢復原工具占高。
- 下一波按鈕被舊手機 CSS 的 `36px !important` 覆蓋，已改44px；文字本身已符合容器，未以隱藏裁切處理。
- 測試時鐘原在遊戲啟動後才安裝，部分 runner 遺失原 RAF 或 pauseAt 落在過去，屬驗證程式問題；改為頁面啟動前安裝、明確未來時間暫停，仍由正式 RAF 推進。
- 病毒目標在兩次存檔間可能已清除，測試改為每個觀察點先合法暫停再讀取最新局面，避免依舊快照點不存在菌群。
- 原演練按鈕及「細胞質內感染」的相容文字恢復；進入其他關卡時清除舊選取模式／教學，避免跨關帶入抗體指定狀態。
- 手機實看腸上皮仍過於團塊化，改用有刷狀緣的柱狀細胞、杯狀輪廓；口腔用連續扁平六邊上皮。腸關主要場地標為黏膜組織間隙，剖面同步區分腸腔／組織側；淋巴組織改用獨立基質與 CD4 剖面，不套上皮屏障。

後續修正：統一控制器與展示使用 `performance.now()` 的單一時基並夾住負的 frame delta，防止受控時鐘換基準後累積負時間。一般遊玩仍以0.2秒固定步進；測試不直接推進引擎。抗體／C3b 狀態與資訊肖像使用相同的綠Y／黃三葉辨識，其他關卡肖像改為對應病原，避免流感／念珠菌仍顯示肺炎鏈球菌。M3 開場直接保留6份活菌於巨噬吞噬體，確保本關確實需要控制既存感染，而非只在建立胞內感染前清掉胞外波次。不同關卡的事件文案不再套用肺炎鏈球菌「莢膜」描述。

受控時鐘的進一步處理：部分 CI runner 在已有活動 RAF 的頁面由即時切為暫停時，出現時鐘佇列競爭，時間增加但沒有再派送遊戲 RAF。驗證現改為空白頁就安裝並暫停時鐘，再導覽啟動遊戲；建立新關卡後先派送影格以確認模型畫面。這是測試啟動順序修正，沒有注入規則狀態、略過結算或把失敗改成通過。
