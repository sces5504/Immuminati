# C「柔光微觀立體」美術與動畫製作規格

版本：1.0　日期：2026-10-17　狀態：美術方向與動態要求已由使用者確認。

本文件是 [主規格 v1.1](../Immuminati-spec.md) 第 11 節的製作細則。正式方向只有 C，A／B／D 是歷史比較，不是可自行替換的候選。預設必須有動畫，包含玩家等待時的微幅漂浮，以及每種實際行動的對應表演。

![C 柔光微觀立體：桌面、手機、角色參考](c-soft-micro-3d.png)

## 1. 視覺目標

做出能操作的柔光微觀世界：膜的半透明、細胞核的體積、顆粒的層次、接觸陰影與組織起伏。細胞是可辨識的生命體，不畫成人形角色，也不加服裝、裝備或武器。

- 細胞：紫／藍的細緻膜與核，柔和高光、適量胞內顆粒，避免塑膠玩具質感。
- 組織：玫瑰、粉紫與較暗的凹處，低起伏、清楚的區域輪廓，背景細節不能壓過單位。
- UI：冷白面板、海軍藍文字、亮藍主要互動，琥珀／珊瑚預警。文字由介面排版，不烘焙進圖。
- 正式色彩以 C 圖為基準；選取、警告、感染等另有輪廓／圖示，不能只靠色相。
- 主光源、陰影方向、邊緣柔度與視角一致。角色切圖不可各有不同地平線或不相容光源。
- 角色大小代表操作單位與辨識需求；百科說明這不是細胞與病原的真實比例尺。

建議初始 UI token：背景 `#F4F6FF`、主要文字 `#14214F`、互動藍 `#159BFF`、次要藍 `#24558A`、預警琥珀 `#FFB629`、危險珊瑚 `#F06470`。實際對比與整體視覺在原型調整，不能任意換成另一種美術方向。

## 2. 場景與素材必須拆開

分層順序：組織底圖 → 區域／連線／作用範圍 → 局部效應 → 單位接觸陰影 → 細胞／病原 → 前景作用 → 選取與狀態標記 → 可操作 UI。

每個單位都獨立繪製、命中測試與動畫。位置使用區域內的標準化錨點，版型變化時重算展示位置；漂浮偏移不修改邏輯區域。主介面不得以整張 C 預覽作底圖後加熱區，也不能只對整張圖縮放、平移來冒充角色動畫。

首版可用 2.5D 去背切圖、分層形變與序列影格；沒有必要為選定畫風先做完整即時 3D。CSS／Web Animations API 負責可組合的位移、旋轉、選取、呼吸與播放控制；局部膜形變、包覆、分裂等用分層或序列素材完成。只有確有需要且已驗證效能時才引入額外繪圖引擎，不讓渲染選擇侵入規則模組。

## 3. 待機動態

| 項目 | 原型起點 | 驗收要求 |
| --- | --- | --- |
| 漂浮 | 各軸約 2–5 CSS px，週期約 3–6 秒 | 平滑、低幅度、各單位不同相位，不同步排舞。 |
| 姿態 | 約 ±2–4 度旋轉，約 1–2% 呼吸縮放 | 不能把旋轉或呼吸變成難以點選的抖動。 |
| 局部生命感 | 膜／偽足小幅形變、核與顆粒輕微相對運動 | 最初動態場景即須有局部變化，不能只有整張切圖上下平移。 |
| 選取狀態 | 穩定輪廓、短暫輕抬升 | 選取環與點按區始終對應同一單位，輪廓不遮住狀態。 |
| 病原 | 小幅姿態、膜或菌絲端部微動 | 沒有繁殖事件時不增加個體；沒有轉換事件時不改變形態。 |
| 組織 | 極少量背景微動與局部光變 | 細胞與重要資訊保持清晰，背景不成為主要動態來源。 |

待機預設開啟，思考、等待下指令或打開非全屏側欄時持續。死亡、已清除、離場角色停止待機；受感染或活化者切到對應外觀。動作播完後平滑回到新位置的待機，不跳回原點。

視覺相位由展示層穩定 ID 等資訊產生，不消耗引擎的 seeded RNG，不每幀寫存檔。位移、呼吸、選取分不同容器／變換層，避免彼此覆蓋 transform。

## 4. 細胞造型與動態差異

| 角色 | 固定辨識特徵 | 動態重點 |
| --- | --- | --- |
| 巨噬細胞 | 較大的不規則形體、彎曲核、囊泡與偽足 | 較慢的形變與漂浮；吞噬時偽足延展與包覆。 |
| 嗜中性球 | 分葉核、細緻顆粒與圓潤但有彈性的膜 | 較短促的姿態變化，作用時可見符合機制的顆粒／胞外反應。 |
| 樹突細胞 | 細長分枝與可辨識的中心胞體 | 突起柔和擺動；取得抗原、攜帶與呈遞有連續狀態。 |
| NK | 清楚的淋巴細胞輪廓與顆粒特徵 | 與合法感染宿主接觸後作用，不當成遠距雷射砲。 |
| CD8 | 可辨識 T 細胞輪廓、標籤與特異性狀態 | 接觸、作用、離開；只處理引擎判定合法的感染宿主。 |
| Th1／Th17／Tfh | 同家族視覺語言，搭配清楚標記與不同作用圖示 | 向接收細胞／組織傳訊、接收者變化；Tfh 主要在淋巴結面板。 |
| B 與分化狀態 | B 的識別與後續漿母／漿細胞分化可追蹤 | 結合、互動、分化及抗體來源分開呈現。 |

活化、感染、記憶、位置、死亡是不同維度；不能靠「變紅」同時表示所有意思。HIV 潛伏背景的資訊與可攻擊目標條件分開，不能為動畫方便使 CD8 看見所有潛伏感染宿主。

## 5. 事件與動作對照

以下名稱是新專案的事件契約起點；若實作時調整名稱，需同步引擎、展示映射、測試與文件。UI 選取／驗證失敗屬介面回饋，其餘是規則事件，不能反向由動畫觸發規則。

| 來源／事件 | 表演順序 | 結束後必須保留 |
| --- | --- | --- |
| UI 選取 | 短選取環、輕抬升、合法目標提示 | 選取輪廓、可操作面板。 |
| UI 指令不合法 | 控制項短提示及原因 | 原狀態、原 AP，不播成功 clip。 |
| `UnitMoved` | 沿合法連線移動、適量形變與柔和加減速 | 新區域錨點、方向與待機。 |
| `PathogenEngulfed` | 靠近→偽足包覆→目標進入宿主 | 若仍存活，胞內負荷／狀態；不能一律消失。 |
| `PathogenCleared` | 清除對應目標、縮退／淡出 | 正確負荷與相關殘餘物紀錄。 |
| `OpsoninApplied` | 正確分子標記附著在合法目標 | 可辨識的調理標記，不直接演成擊殺。 |
| `NeutralizationApplied` | 結合到合適病毒／目標並顯示阻斷狀態 | 事件指定的中和作用，不暗示已治好感染宿主。 |
| `SignalEmitted`／`CellActivated` | 來源局部擴散或傳遞→接收者反應 | 接收者的活化／作用狀態及剩餘時間。 |
| `AntigenAcquired`／`AntigenPresented` | 取得→攜帶→相應位置互動 | 呈遞進度、後續活化等待；不瞬間生成完整 T/B 反應。 |
| `InfectedHostKilled` | 接近→接觸作用→宿主凋亡→殘餘物處理 | 依引擎決定殘餘感染的去向，不能一律清空。 |
| `RecruitmentRequested`／`UnitArrived` | 佇列提示→等待→由對應入口抵達 | 預留／占用容量、單位可用狀態、待機。 |
| `CellDifferentiated` | 保留識別關係的形態／細胞內容變化 | 新效應狀態、能力與標籤。 |
| `PathogenReplicated` | 分裂／出芽等符合目標形態的表演 | 分裂後負荷，畫面數量上限和抽象群體規則一致。 |
| `HostInfected` | 合法病原侵入宿主，轉為內部感染提示 | 宿主識別、區室與感染狀態。 |
| `MorphologyChanged` | 白色念珠菌的對應形態漸變／菌絲延伸 | 新形態與合法目標規則。 |
| `TissueDamaged`／`TissueRecovered` | 對應區域短變化→更新長期外觀 | 組織完整度、評星相關狀態。 |
| `UnitRemoved` | 相應死亡／離場表演，清除選取與特效 | 角色不再待機或保留可點擊殘影。 |

一般選取回饋約 120–180 ms；主要動作約 600–1,200 ms 起步。吞噬、呈遞及宿主處理可依可讀性略長。多單位不相關事件可並行；同一來源／目標的因果順序不可倒置。大量同類自動行為採分組與摘要，不要求玩家觀看數十次完全重複動畫。

## 6. 播放架構與控制

建議的展示內部分工：

```text
presentation/
  idle/         漂浮、呼吸、局部待機
  clips/        位移、包覆、作用、分裂、凋亡等表演
  eventMap/     領域事件到可組合動作的映射
  playback/     佇列、並行群組、速度、取消、跳過
  visualState/  播放中的展示快照與短暫物件
```

1. `application` 驗證並提交指令，取得行動前／後狀態與事件。
2. 權威結果只計算一次；展示從前狀態依事件推進到後狀態。
3. 播放中鎖定新的戰鬥指令；百科、設定與跳過仍可操作。
4. 動畫完成或跳過後，展示與權威結果同步、清理短暫效果、解除鎖定並恢復待機。
5. 卸載、切頁、取消、讀檔及錯誤恢復均要清理動畫控制器，不能重複觸發領域事件。

`animationend`、`Animation.finished`、序列影格回呼都只能協調展示，不能直接殺死病原、補 AP 或推進回合。動畫素材尚未載入時保留文字與可理解的展示，缺少必備動作要在開發驗證報出，不能悄悄當作完成。

正常、加速、跳過與減少動態效果是同一組事件的不同展示。已提交結果後關頁，不在讀檔時再結算；依主規格重建最終畫面。HIV 結局文字未呈現前不能僅因跳過動作就把結局記為已看。

## 7. 正式素材交付清單

目前 repo 的 PNG 是概念參考。以下是開發需要製作的項目，不代表已經存在：

| 類別 | 首版需求 |
| --- | --- |
| 組織 | 各案例需要的組織底圖、區域邊界、連線、損傷與局部修復層；淋巴結支援區。 |
| 細胞 | 九種操作角色的去背圖／分層，對應需要的活化、感染、分化、凋亡狀態。 |
| 病原 | 肺炎鏈球菌、所選沙門氏菌血清型、結核分枝桿菌、流感 A、白色念珠菌酵母／菌絲、HIV。 |
| 動作 | 基本待機、選取、位移；依角色需求製作偽足／包覆、呈遞、接觸殺傷、分化、分裂與形態轉換。 |
| 特效 | 抗原、調理、中和、訊號、局部作用、感染標記、組織受損、到場與殘餘物。 |
| UI | 選取環、合法目標、等待進度、圖示、狀態標籤；文字不放在圖像內。 |
| 動畫資料 | 素材 manifest、錨點、顯示外框／點擊外框、clip 定義、事件映射與狀態切換。 |

可用分層形變完成的動作不必全部製作大量逐格圖；需要輪廓變化的包覆、分裂等不可只用淡入淡出代替。PNG／WebP 保留透明背景，序列圖集保持固定原點、清楚邊界與足夠間距，避免動畫跳位／相鄰影格滲色。

命名方向：`cell/macrophage/...`、`cell/neutrophil/...`、`pathogen/pneumococcus/...`、`tissue/lung/...`、`effect/opsonization/...`。素材以穩定 ID 對應內容，路徑不是免疫機制的判斷依據。正式圖集建議先控制在 2048×2048 以內作載入與記憶體測試，這是製作預算，不是所有裝置的硬性能力上限。

每個素材定義至少記錄：`visualId`、來源檔、圖像尺寸、錨點、邊界、可用 clip、狀態變體、製作方式與授權／來源。缺少素材要有可追蹤清單，不能把佔位物件標成已完成。

## 8. 手機、效能與動態偏好

- 動作要在桌面與直向手機都看得懂；可點擊外框穩定且至少 44×44 CSS px，沒有 hover 的操作也完整。
- 目標為桌面接近 60 fps、中階手機穩定 30 fps 以上；記錄裝置、瀏覽器、單位數與效果數。雲端模擬只能證明對應環境的排版／互動，不能取代未測真機的效能結論。
- 背景粒子、模糊、層數與高解析度圖集先設定預算；畫面外或被全屏百科遮住的裝飾性動態可暫停。
- 頁籤隱藏時暫停展示時鐘或安全快轉展示；不可使回合、增援與感染依真實時間自動進行。
- 避免每幀更新整個 React 狀態樹或讀寫 localStorage。動畫系統與戰鬥狀態更新分開。
- 預設動畫開啟，提供動作速度及待機動態選項；尊重 `prefers-reduced-motion`。降低模式使用短淡入／狀態標記／文字，不要求持續漂浮或大幅縮放，也不改變規則結果。

## 9. 製作順序與完成定義

1. **最初動態樣板**：C 風格的一個組織區域、巨噬／嗜中性／樹突與肺炎鏈球菌，獨立分層；5 秒不操作也看得到自然但低幅度的生命感。
2. **動作樣板**：選取、調度、招募、調理、吞噬，以及吞入後「清除／仍存活」兩種分支；與事件／紀錄一致。
3. **完整 M1**：接入真正規則、AP、區域、百科與勝敗；同時交付桌面與手機動畫。此時就錄影，不能只交靜態截圖。
4. **M2 擴充驗證**：胞內狀態、訊號與呈遞流程依新事件組合，不重寫既有動畫／引擎。
5. **後續四關**：補足各自的宿主、病毒、真菌形態與 HIV 狀態表演；維持同一美術語言。

每階段交付：素材及 manifest、事件映射清單、動作可讀性檢查、正常／加速／跳過結果一致性、短錄影、已知缺項。缺少專用動畫的能力不能宣稱正式完成。

## 10. 必過檢查

- [ ] 同一戰場中各單位分別漂浮，且相位不同；只移動整張背景不算通過。
- [ ] 角色有柔光立體材質與局部形變，背景與按鈕不搶資訊。
- [ ] 待機不造成邏輯位移，選取與點擊始終對準角色。
- [ ] 所有實際可執行的行動／自動事件有對應表演；吞噬、呈遞、訊號、毒殺有不同語彙。
- [ ] 吞入存活病原保留胞內狀態；死亡、離場與殘餘物不出現錯誤漂浮。
- [ ] 加速／跳過／降低動態／背景切換與正常播放得到相同結果，不重複扣點。
- [ ] 連點不重複派送；切頁、讀檔及撤銷不留下殘影、錯位或卡死鎖定。
- [ ] 360 CSS px 手機的目標、狀態、AP 與結束回合可用；錄影能看出待機及行動。
- [ ] HIV 的動畫與介面不在結局前劇透必敗，不偽造免疫機制，也不宣稱現實無法治療。
