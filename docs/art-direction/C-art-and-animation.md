# 柔光微觀立體：展示與動畫規格 v2.4

適用[主規格 v2.4](../Immuminati-spec.md)。最新八項任務明確授權改善組織及細胞模型；取代 v2.1 的「模型不改」，同時保留原 UI／構圖／操作與整體柔光風格。

## 保留與改善

實際已檢視 [C 概念圖](c-soft-micro-3d.png) 及原版[桌面](../evidence/tactics/desktop-field.png)／[手機](../evidence/tactics/mobile-field.png)。沿用 Three.js 場景、既有 HUD、指揮列、選取／調度、相機、手機布局及歷史動作；不改換入口或把預覽圖當戰場。

本輪肺部模型採開放剖視：相通肺泡腔、連續肺泡隔、薄上皮接合、沿隔微血管、血管增援入口，以及不同顏色的淋巴引流入口。移動通道與隔上開口對應；不再以一圈散亂甜甜圈／石塊代表組織。相鄰肺泡形成連續背景。這是教學模型，不按真實比例，不是病理切片重建。

`tissueProfiles` 選擇肺、口腔、腸黏膜的結構方向。正式 M1 使用肺；其他器官目前只有 profile／基礎建模分支，沒有新關卡或完成醫學建模的宣稱。

細胞採連續膜面，偽足／樹突連接本體；巨噬彎曲核、嗜中性分葉核及核間連絲、淋巴球較緻密圓核、細胞毒顆粒、漿細胞偏心核及粗面內質網形態應可區分。顏色只輔助辨識，角色機制不可只靠改色。程序幾何與材質皆可獨立替換；不要求日後重寫引擎。

## 宿主組織與剖視 v2.3

所有關卡共用可選宿主細胞與同一位置語意。M1 第一型肺泡上皮為沿隔貼合的薄片、低矮核，第二型有較飽滿核與層板小體示意；內皮沿組織側血管排列。移除先前未綁定任何細胞的裝飾核，讓可見組織細胞對應權威 ID。仍為程序教學模型，不宣稱真實尺度或完整解剖。

中央明標「肺泡腔 · 細胞外」，組織側入口與腔面有可辨識的帶狀區隔。剖面圖解釋腔面→上皮／基底膜→間質→內皮／血管腔；肺泡隔並非單一細胞膜。原 UI／鏡頭／調度方式保持。

附著於組織的上皮／內皮保持錨定，不能像游離免疫細胞一樣漂浮而破壞屏障層次。

局部剖視由選取細胞的權威區室與活負荷驅動；主場景所選宿主膜透明化，資訊面板放大顯示膜、質、核及實際吞噬體／感染內容。未感染不畫假病原。吞噬體處理中與持續存活分開標示；活菌不因吞入動畫結束就消失。病毒核內區室只預留資料／剖視分支，不能當成病毒關卡完成。

## 動作

- 待機：各單位相位不同，呼吸／漂浮、膜面局部 morph 及突起變化；不改權威位置或 RNG。
- 移動、選取、增援：延續既有接觸距離、沿通道走入、地面選圈與路徑。個體分別動畫，不鎖整場。
- 吞噬：接近 → 偽足包覆 → 吞入 → 清除／囊泡內存活分支。不能只閃光或冒數字。
- 調理：C3b 為附著小點，抗體為 Y 形結合，兩者都不以演出直接計算傷害。
- 細胞毒：接觸處形成局部穿孔／顆粒轉移，感染宿主縮小及膜起泡／凋亡小體；不得做成射擊所有細菌。NK／CD8 共享效應演出，辨識規則不同。
- B → 漿細胞：權威分化事件後替換模型，顯示偏心核與分泌結構；分泌事件／抗體附著表示支援，不是抗體子彈。
- 訊號、呈遞與活化：由狀態、時間流程、情境文字及因果紀錄解釋；不以通用爆炸充當訊號功能。

引擎先提交結果與事件；動畫只讀取，不能扣資源或修改勝敗。1×、2×、降低動態及重新讀取對相同步數的權威結果一致。

## 互動與手機

維持抓取式拖曳：手向右／上，地標同向；旋轉／縮放後仍正確。拖曳放手不得誤下命令。模型、標記及選取需投影一致，列表可選擇密集單位。

新控制採原深色半透明面板語彙：自動尋敵、1×／2×、免疫機制、教學。主要操作至少 44 CSS px；直向教學卡不能遮住當步操作。手機增援清單可捲動，禁用原因直接顯示，不依賴 hover。

C3b 小點與抗體 Y 形由各自權威期限控制，同時有效時均呈現。血管／淋巴沿地形，組織側色帶直接混入地形頂點顏色，不加會穿插的平面。保留宿主權威 ID 與模型 adapter。
