# C「柔光微觀立體」美術與動畫規格 v2.0

更新：2026-10-17（Asia/Taipei）。適用 [混合型可暫停 RTS 主規格 v2.0](../Immuminati-spec.md)；本檔規定美術與展示品質，不另定玩法。

## 1. 保留畫風，重做不合格的形體

必須實際開啟 [C 參考圖](c-soft-micro-3d.png) 觀察柔光、膜、內部結構、細胞輪廓、組織深度與資訊層級。C 仍為唯一正式方向；A／B／D 是歷史探索。**圖中的回合、AP、End turn、分區版面不是新版 RTS 的規則或固定布局。**

使用者看過現有版本後，明確指出 3D 建模不好看。既有 [桌面原型截圖](../evidence/tactics/desktop-field.png) 只用於定位問題，不能當作已通過的美術基準。程序建模、模型可動、功能測試通過，都不能單獨證明符合 C。

| 現有問題／應避免                           | 新版本的可檢查要求                                                                                         |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| 巨噬細胞像紫色球體／葡萄堆，突起像拼裝零件 | 主體是連續、不規則但柔和的膜面；偽足從膜自然伸出並漸細，根部相連。內部細胞核與胞器可辨，不浮在膜外。       |
| 嗜中性球只有一顆外殼球與隨機小球           | 淡色、微透的完整胞膜包住可辨識的分葉核與細顆粒；核葉有連結，不能把外部衛星球當核葉。                       |
| 樹突細胞像放射硬尖刺／海膽，枝條與身體斷開 | 主體與多支漸細、略有分叉的突起連續，長短有變化；動作有方向與柔性，不整齊排成僵硬星形。                     |
| 病原像任意藍色彈珠堆                       | 肺炎鏈球菌保留成對球菌／短鏈與可見莢膜層，調理前後可區分；群體負荷不只一串數字。                           |
| 地表充滿重複粉紅甜甜圈／粗管環             | 肺部組織有連續、低對比的肺泡隔壁、腔隙與微血管關係，尺度／方向自然變化。不得用相同圓環滿鋪冒充肺泡地形。   |
| 硬塑膠亮斑、過曝高光、內部結構混濁         | 柔和主光＋環境補光，微透膜、適量粗糙度、輕接觸陰影；能同時讀出表面和內部，不靠刺眼鏡面或全透明維持立體感。 |
| 組織與細胞同樣搶眼、HUD 壓滿戰場           | 降低背景紋理及飽和度；病原、細胞、訊號、選取與組織有清楚層級，手機縮小後仍辨識角色。                       |

不用增加擬人眼睛、嘴、武器或怪獸尖刺來補救辨識度。配色可微調，但形態先能辨識；不能只靠紅綠色區分狀態。

## 2. 製作方式與分層

畫面要有微觀立體感，不要求為使用 3D 而使用 3D。可採改良即時模型、原創分層 2.5D rig／預渲染素材，或經驗證的混合方案。選擇須滿足連續位置、鏡頭、獨立選取、局部動態與吞噬，並依樣板與手機效能說明取捨。

- 組織地形、血管、免疫細胞、病原、訊號、接觸／動作特效、選取及 UI 分層；每個邏輯單位能獨立移動與播放。
- 細胞內部結構與膜分開控制；核與囊泡不穿出膜。偽足與膜變形應連續，不用幾根脫離身體的圓棒代替包覆。
- 跟隨固定斜視角的 2.5D 可以採平移／縮放；若啟用旋轉，所有角度都需正確，不能把紙片側面露給玩家。自由旋轉不是交付必要條件。
- 不把 C 圖或 ImmuneQuest 截圖鋪滿後加點擊區。不得把概念預覽宣稱為已取得的透明、分層素材包。
- 資產應原創或授權可用；記錄來源、授權、用途、版本與佔位狀態。圖片／模型以專案 base 載入，不依賴製作者本機。

## 3. 角色、組織與 UI 的視覺語言

| 層            | 方向與辨識重點                                                                                                        |
| ------------- | --------------------------------------------------------------------------------------------------------------------- |
| 巨噬細胞      | 較大、不規則軟膜與寬偽足，偏藍紫；曲面內部有核，攝入囊泡與消化結果清楚。                                              |
| 嗜中性球      | 較小、淡色膜與紫色分葉核，細小顆粒；可快速沿趨化前進，不與巨噬只差大小。                                              |
| 樹突細胞      | 細長、漸細分枝，成熟／攜抗原有局部可讀標記；遷移有明確出口與去向。                                                    |
| 後續 NK／T／B | 保留淋巴細胞基本形態，以核質比例、柔和配色與標記區分；活化／效應／記憶屬狀態，不拿裝備升級表達。                      |
| 肺炎鏈球菌    | 小型雙球對／短鏈，淡藍或青色，半透明莢膜；大小、密度與組織比例一致。                                                  |
| 組織／血管    | 低對比暖粉、玫瑰與淡紫，連續結構；血管內外可辨。損傷是紋理／完整性／色澤變化，不靠整張背景變紅。                      |
| 訊號場        | 可切換的平滑梯度，含圖例、來源與強弱；不同訊號有配色／紋理／標籤，不能遮掉選取目標。                                  |
| 介面          | 參考 C 圖的清爽、圓角與深色文字，可用淺底面板或少量深色浮層；不要沿用現有大塊深色面板擠壓戰場。對比、字級和觸控優先。 |

地圖有密集細胞時，以聚合代表、標記／列表或視覺散開維持閱讀。**美術與效能不得以每區 3 個、全場 7 個等名額限制解決擁擠。** 群組輪廓、數量與真正可選對象須一致。

## 4. 待機生命感與暫停

每個單位獨立組合低幅度漂浮、呼吸、膜局部起伏／偽足微動。相位、振幅與節奏有所差異，但來自獨立視覺種子，不消耗戰鬥 RNG。不同單位不能完全同步放大縮小。

- 動作幅度小於主要輪廓辨識需求；選取／命中區跟隨可見位置，不因浮動變得難點。
- 待機只影響展示變換，不能讓單位穿牆、改距離或多一次作用。
- 真正移動與動作期間平滑混合，不重播待機造成跳位；死亡／清除後停止該邏輯物件待機。
- 模擬暫停時可保留低幅度、無進度含意的膜呼吸；路徑移動、跨內皮、攝入進程與淋巴結進度均停住。UI 明示暫停。
- reduced motion 降低或關閉漂浮、形變與鏡頭動態，保留可讀的選取、狀態與結果。

## 5. 必交付動作與事件映射

| 機制             | 必須看得見的過程與結果                                                                         |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| 選取／指令       | 輪廓／柔和環、角色與群組標記、合法目標與移動目的地；拒絕原因就地可查。不是全畫面泛白。         |
| 巡邏／移動／趨化 | 柔性朝向及前緣延展，沿權威路徑接近；趨化時能由訊號視圖解釋方向。避免所有細胞像棋子同速滑行。   |
| 調理             | 補體／抗體標記在病原表面逐步附著，保留被調理狀態；不在附著時直接讓菌群爆炸。不同媒介標籤一致。 |
| 吞噬             | 接近、接觸、偽足伸出且連續包覆目標、膜合攏、目標進入胞內囊泡。吞入前不先把病原直接刪掉。       |
| 已清除           | 在攝入後顯示消化／分解、碎片減少與囊泡退場；才得到明確的清除回饋。                             |
| 胞內存活         | 吞入後仍有具活性視覺的囊泡內病原與宿主標記；不能播放相同的死亡消失、也不能把囊泡畫到宿主外。   |
| 訊號產生／場     | 來源細胞局部釋放，實際場隨模擬擴散／衰減；可有微粒幫助閱讀，但微粒不取代場資料。               |
| 募集／內皮       | 局部內皮活化，細胞從血管內到外並擠過邊界，再朝訊號移動；有等待與到場節奏，不在目的地瞬間彈出。 |
| DC／淋巴結       | 抗原攝取／攜帶、成熟狀態、離開組織、交通與面板階段轉換；抗體支援回到組織後是調理等正確效果。   |
| 發炎／組織損傷   | 局部、漸進且依損傷原因變化；辨別「訊號強」與「組織已受損」，不把兩者一律畫成火焰。             |
| 病原繁殖／擴散   | 增加代表密度或群體分出並沿通路擴散；不能只更新數字而空間壓力毫無改變。                         |
| 結算             | 停止生理推進，呈現明確的感染與組織結果、M1 星等及重要因果。RTS 沒有「回合結果」按鈕。          |

M1 必交付它實際發生的動作。胞內存活分支可先以受控機制展示與測試影片驗證，標明不是本關常見病程；後續病毒細胞毒性、菌絲處理等在相應關卡另製作，不以通用光圈冒充完成。

## 6. 權威結果與連續動作

引擎提交動作狀態／結果與事件，展示按事件 ID 播放。攝入可有權威的起始／完成階段，動畫不得靠 `onComplete` 計算攝入成功、傷害、資源或勝敗。

- 正常、2×／4×、略過與 reduced motion 以相同步數得到相同結果；視覺可縮短、合併低優先事件，不能漏規則。
- 同時多個行為需有每單位／目標的合理動作層與交接。不能因全局播放器播放一個吞噬就鎖住其他單位或整個戰場。
- 短暫展示殘影只為表現已提交的包覆／分解，不可再被點選、攻擊或二次吞噬。不要讓已完成結果的靜態紀錄和延遲動畫互相矛盾。
- 新指令、目標已清除、死亡、讀檔、暫停、切頁／返回與事件重送須有取消／銜接政策，不能卡在吞噬一半、回跳起點或重複消耗。
- 略過不影響模擬時鐘；正常加速則增加固定規則步。狀態標記與文字結果不能隨影片一起被略過。

## 7. 鏡頭與觸控驗收

遵守 [主規格第 4 節](../Immuminati-spec.md#4-連續戰場與操作)。抓住地圖向右拖，畫面裡的地標跟著向右，不是向左。所有圖層一起移動，不能地形正向、選取環反向。縮放／旋轉後再次測方向、點選與標記對位。

桌面及直向手機都必須實測：點按選取不誤拖；拖地圖放手不發出移動命令；密集單位可用列表／循環選取；觸控不被瀏覽器頁面捲動搶走戰場手勢。地圖手勢與 UI 捲動範圍清楚分開，支援重設鏡頭。

## 8. 開工樣板與品質檢查

先做小型可操作樣板：一片有血管的組織、三種 M1 細胞、未調理／已調理雙球菌，以及待機、移動、吞噬、清除／存活分支。不以更多雜訊、球體或粒子掩蓋基礎形體問題。

樣板至少留下：

1. 遊戲預設縮放的桌面與直向手機畫面，辨認細胞不必放大；另留近景檢查膜、核、枝條連接與表面材質。
2. 連續至少 5 秒的多單位待機，證明不同相位與局部變化。
3. 接近 → 包覆 → 吞入 → 清除／存活短錄影，可逐幀看見完整過程。
4. 抓取式拖曳及縮放，確認選取／接觸／訊號對位。
5. 相同事件在正常／略過／降低動態的權威結果比較；近景影片不能代替手機完整操作驗證。

實作者按本檔自查並記錄具體缺項，不新增「每一階段都要等使用者批准」的流程。若有素材缺口，繼續引擎、內容與其他可獨立工作，明列佔位與差距；未完成核心動作或仍採被否定的形體時，不宣稱 M1 美術已達標。

## 9. 資產與最終證據

維護實際使用的素材清單，至少記錄 ID／路徑、角色與層、來源／授權、已完成或佔位、對應動作、版本與缺項。新增素材目錄與檔名由實作者決定，不把尚未建立的檔案寫成已交付。

最終桌面／手機錄影包含待機、調度、正向地圖拖曳、調理、包覆吞入、募集到場、趨化／訊號、淋巴結及結算。記錄瀏覽器、viewport、繪圖環境與效能限制；模擬觸控不是實體手機，靜態截圖不是動畫證據。原型歷史影片不作 v2.0 完成證據。
