## 2. 保留範圍

沿用 `src/tactics/presentation/BattleScene.ts` 的場景、角色、動畫與相機；沿用 `TacticalApp.tsx`／`tactics.css` 的首頁、HUD、浮層、指揮列、百科、紀錄、結算及手機響應式布局。

不換引擎、不新增平行渲染入口、不換成簡模或另一種美術。不另啟動美術重製 agent；未來有新的明確美術任務才調整。

## 3. 玩法修改可帶動的最小展示調整

- 修正地圖拖曳反向、投影／選取對位、重疊點選或動畫殘影等可重現 bug。
- 規則變更後，在現有位置更新數量、成本、等待、禁用原因與狀態。例如取消區域容量後不留「已滿」或 3/3 名額，但不因此重排整個 HUD。
- 新增玩法真的需要的標記或提示時，延續原有元件、色彩、字級及互動語意，避免同屏資訊膨脹。
- 視覺散開、聚合或效能修正不得改權威位置／負荷，不得藉技術預算恢復區域名額，也不能刪除核心動作。

## 4. 核心動作不退步

保留各單位不同相位的待機漂浮、呼吸與膜／偽足微動；待機不改邏輯座標或戰鬥 RNG。移動與選取不互相覆寫。

吞噬保留接近 → 接觸 → 偽足包覆 → 吞入 → 清除或胞內存活的不同結果；調理是表面附著、不是即時殺菌；增援由入口到場、不是目的地瞬移。訊息與紀錄對應權威結果，不能全部改成通用閃光／數字。

動畫回呼不扣點、不改感染或勝敗。不同速度、略過、降低動態與重送事件對相同規則步結果一致。背景／暫停／讀檔不造成重複動作、跳位或卡住。

## 5. 鏡頭方向與手機

保留原拖曳、縮放、旋轉、重設手勢與按鈕；修正方向為抓住地圖：拖右地標也向右、拖上也向上。桌面與觸控相同，縮放／旋轉後再次驗證；拖曳放手不能誤下命令。

地形、單位、訊號或狀態標記、選取框必須投影一致。維持直向手機完整點按、主要目標至少 44×44 CSS px、既有列表可選取重疊單位，沒有 hover／右鍵必需流程。

## 6. 對比與驗證

玩法改動後以同 viewport、相機與可比較局面留下桌面／手機截圖，對照基準檢查模型、色彩、構圖、HUD 與指揮列。必要的規則文字／數量變化另列，不能把整套美術重製說成小調整。

保留待機、調度、包覆吞入、增援及結算短錄影。若修改鏡頭，錄製正反拖曳與點選；若改規則，驗證動畫仍對應結果。記錄瀏覽器、viewport、真機或觸控模擬及效能限制，不以舊影片當本輪測試。

## 7. 素材與介面邊界

既有素材／程序模型與展示邏輯保持和規則分離。未來確有素材替換需求時，可沿用穩定 ID、adapter 與錨點，不必為此先做通用素材框架、預覽工具或替換範例；這些不再是本輪玩法優化的強制交付。

保存歷史來源／授權與證據，佔位內容如實標示；原立體版不因曾有重製提案而整體被標成佔位。本次只更新文件，不代表新動畫或模型已製作。
